# profile-atlas 设计

## 要解决的问题

在 AI 时代，能力不只体现在公司里写下的代码，自己学习、动手做出来的实验项目同样算数。可是自学项目直接写进简历，
读的人无从核实，也看不出深浅。profile-atlas 解析一个人的 GitHub，把项目变成**带证据的清单**，再按岗位生成不同侧重的简历。

## 四层结构

```
① 知识层              ② 项目层                        ③ 理解层                 ④ 侧写层
AI 知识地图     ──▶   一个项目 = 一个仓库        ──▶   代码地图、讲解卡片  ──▶   profile-atlas
技术节点和关系        .portfolio/project.yaml          （可选）                  岗位 → 选项目、写、核对、渲染
```

- 技术和项目是多对多关系，这个关系存在**数据**里：清单的 `techs` 引用知识地图的 slug，并同步成仓库 topic。
- 清单里用到、但知识地图还没有的技术（`proposed`），会在 `check` 的 `kmap_missing` 里列出来，作为知识地图的扩展待办。

## 核心规则：没有证据，就没有内容

| 环节 | 检查 |
|---|---|
| `check`（项目清单） | 证据文件必须已提交；`quote` 必须原样出现在文件里；指标数字必须能在证据里找到（允许证据更精确）；只有 README 自述作证时给出警告；`scale: smoke` 给出提示 |
| `plan`（选项目） | 只收 `status: active / done` 的清单，和资料里 `verified: true` 的项目；其余写明排除原因 |
| `verify`（简历草稿） | 每一项都要引用计划里的条目；标题、tagline、bullet 里的每个数字都要在该条目的事实里找得到；smoke 级指标不能和“提升 / 优于 / →”一起出现 |
| `render`（公开版） | 输出里不能出现任何身份信息，出现即中止并删除旧的公开版 |

文字交给 agent：按岗位换角度、压缩、合并。事实交给工具：数字从哪来、项目在不在、结果有没有被夸大，都由代码判定。

## 选项目：岗位打分

岗位是一组权重：`weights.topics`（知识地图的方向）和 `weights.techs`（具体技术）。项目里每个技术的得分是
`深度权重（core 1.0 / used 0.6 / touched 0.3）× 岗位对它或它所属方向（含上级方向）的权重`。项目得分只取**最相关的三个技术**，
避免一个项目靠堆砌大量弱相关的技术胜过围绕岗位核心技术做的项目；非 smoke 的量化结果只加一点点分，用来打破平局。

## 哪些项目进入简历

| 字段 | 取值 | 含义 |
|---|---|---|
| `status` | `active`、`done` | 进入简历生成 |
|  | `idea`、`archived` | 一律不进入任何简历 |
| `visibility` | `public` / `summary` / `hidden` | 进入简历后在公开版里的展示程度；完整版不受影响 |

想保留仓库、但不让它出现在简历里：`status: archived`，必要时在 GitHub 上把仓库设为归档（只读、内容保留、随时可以取消）。

## 隐私：工具开源，数据不开源

| 放在哪 | 内容 |
|---|---|
| 本仓库 | 工具代码、schema、岗位预设、只引用公开项目的样例；不含任何个人数据 |
| 各项目仓库的 `.portfolio/project.yaml` | 项目层面的内容；不写姓名、联系方式、学校、公司 |
| `~/.config/profile-atlas/` | `profile.yaml`（姓名、联系方式、教育、实习与不在 GitHub 上的项目）、`config.yaml`、自定义岗位 |
| `~/.local/share/profile-atlas/<login>/` | 同步的清单缓存、计划、草稿、渲染结果 |

后两个目录如果位于任何 git 仓库内，工具会拒绝读写；数据目录权限设为 700。

两个构建目标：

- **完整版**：全部内容，只在本机生成，PDF 由本人直接发给招聘方。
- **公开版**：匿名。显示 `public_name`；去掉电话、邮箱、论文（论文标题能直接查到作者），默认去掉 GitHub 链接（GitHub 显示名可能就是真名）；
  公司和学校只用别称，没有别称的学校不显示；`hidden` 项目不出现。输出会被不区分大小写地扫描，命中姓名、联系方式、公司、学校、
  GitHub 账号或 `public_redact` 中任何一项就中止，并删除旧的公开版，避免留下过期但含身份信息的文件。

## 同步

`sync` 用 `gh` 当前登录的账号，扫描本人和所属组织（或 `config.yaml` 指定的组织）的全部仓库，找出任意深度的
`.portfolio/project.yaml`（sandbox 仓库每个子目录各有一份），跳过模板仓库。下载先写进临时目录，全部成功后再替换缓存，
中途中断不会留下残缺的缓存。

## 项目组织建议

- 个人账号只放公开的门面；实验和项目放进一个组织，个人主页就不会被琐碎仓库淹没。
- 用组织里的模板仓库新建项目（预置 README 骨架、清单、`docs/metrics/`），或让 project-intake 直接建空仓库并写好骨架。
- 小探索先放进按领域划分的 sandbox 仓库，长成完整项目再毕业成独立仓库。
- 公司代码不进 GitHub：实习经历写在本机资料里，只放脱敏后的事实，简历上与个人项目分栏展示。
